# Private provider transport trust preparation

`scripts/prepare_semantic_provider_trust.py` is a standalone plan/apply/verify operator helper, not a release/activation/mount tool. It generates a new installation-private EC P-256 CA, two serverAuth TLS leaves with distinct exact caller-selected DNS SANs, a public trust bundle preserving the selected host CA input and adding the new CA, and a fresh cryptographic256-bit purpose-separated provider receipt key copied only to the two receiving roles. No old semantic-read/delegation/OAuth key is reused or rotated. CA/server validity limits are explicit arguments, with server validity below CA validity. Renewal/rotation/revocation/expiry operations remain deployment lifecycle work, not automatic side effects of this preparation.

Explicit inputs: installation ID; Gateway container/expected immutable running ID; adapter image ID/source commit/non-root UID/GID; distinct adapter/southbound hostnames; CA/server validity days; absolute selected public CA file and unused snapshot root. Docker/OpenSSL CLI locations are overrideable. Gateway ownership is derived from readonly `id -u/-g` in the selected live container, guarded before/after by scalar ID/image/user/running metadata. The inspect template never selects env/mount/command/secrets. Root Gateway UID/GID is refused. Adapter image source/component/payload labels, native entrypoint and runtime user are checked against the explicitly selected immutable image. No image pull/build/runtime container create/start/switch is performed.

Root-only helper; path ancestors must be root-owned directories without group/world write or symlinks. Public CA input is a bounded root-owned non-writable regular single-link no-follow file, parsed as CA certificates and rejects any private key. Plan reads selected metadata/OpenSSL version/public trust only and creates no snapshot/key/certificate. Apply refuses any existing root/symlink, writes exclusive private intent, generates local artifacts under private umask, verifies certificate signature/purpose/exact hostname and wrong-hostname denial, cert/key loading, runtime ownership and receipt-key pair equality, and rechecks role/public-input stability. Only then it writes an exclusive private success receipt. Failure retains intent/artifacts without success and explicitly forbids blind retry/overwrite. Verify checks exact recorded bindings, owner/mode/link/symlink safety and exact private artifact hashes; it never generates/renews keys. Private key checksums in the root-private receipt are never printed. JSON CLI output is a fixed non-secret metadata allowlist; raw crypto/Docker failures and key/certificate content are suppressed.

Snapshot root and role directories root-owned0700; intent/receipt and offline CA private key root0600. TLS private keys, role leaf certificates and each provider-receipt.key are0600 with adapter UID/GID or observed Gateway UID/GID. Only `ca.crt` and `trust-bundle.pem` are public root0644, safe to read after binding their individual leaf files into a runtime; they contain no private key. Root parent directories stay private. Future installers must use explicit readonly leaf-file mounts into traversable target directories, not bind these root0700 role directories wholesale to non-root workers. The offline ca.key must never be mounted into any runtime image/container. The existing verified Semantic OAuth copy remains untouched and unmounted; this helper does not read it, request tokens, change IAM, publish application policy, resolve/contact providers, replay source jobs or install kernel/network/TLS settings.

Test fixture uses only synthetic public trust and mocked readonly Docker metadata/UID commands. Mandatory CI runs as real root under /root with actual UID/GID10006/10004 ownership (8 tests, no intentional skips), real OpenSSL signing/hostname checks and an actual local TLS positive/wrong-hostname handshake with the prepared leaf/key/trust. Guards cover plan/no write/no secret inspect, image/identity/hostname/validity, public input mode/private-key rejection, private pair/mode/symlink/content drift, partial failure/no overwrite and redacted CLI output. Local restricted-filesystem UID mapping cannot chown10006; those3 integration cases are opt-in/skipped locally and must run in CI with OUF_TRUST_FULL_OWNER_TEST=1. Test fixture parent is explicit (OUF_TRUST_ROOT_FIXTURE_PARENT). Local test socket is loopback only, never a provider call.

Prepared trust is not installed trust acceptance. Separate dedicated southbound configuration/leaf mounts, Java native client truststore binding, source/namespace governance, fixed provider/identity/DNS openings, bounded/fail-closed FQDN lease refresh, kernel lease lifecycle/reboot/offload/IPv6 proofs, production bypass negatives, real provider admission/exchange, Technology Economy review and native Semantic V10 migration-aware release remain open. All installation domain/endpoint/port/network/identity/trust bindings remain parameters. The existing52c0dcf adapter image build payload is unchanged and must not be rebuilt for this helper addition.
