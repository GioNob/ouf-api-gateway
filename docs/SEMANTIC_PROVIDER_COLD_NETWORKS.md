# Cold dedicated provider networks

The plan/apply/verify helper takes explicit installation, network, bridge, table, tool and snapshot bindings. This profile explicitly selects Docker automatic IPv4 IPAM; no subnet or domain is hardcoded. Plan checks names, selected role topology and nft syntax without writes. Apply installs a deny-only inet/native bridge guard BEFORE creating two empty bridges (internal transport and noninternal egress). It checks allocated subnets against all baseline Docker networks, host routes and interface address ranges. No current container is attached; no runtime image, credential, route, IAM or provider operation is performed.

The custom guard must preserve shared rule structure. Docker itself creates network/NAT rules for its new networks; this is reported explicitly. Newly created networks carry an installation ownership label. A private exclusive intent, rules, readback and creation journal precede the final receipt. Existing networks/endpoints and selected role topology must remain unchanged. Verify requires exact network IDs/configuration, empty endpoints and identical owned rule structure, ignoring packet counters. A failure retains guarded partial resources and reports DO_NOT_RERUN_BLINDLY; reconcile the journal rather than overwriting or deleting unidentified resources.

This step proves installation structure, not production packet acceptance, TLS connectivity, DNS lease refresh, restart persistence or provider admission. The independently required real Docker/kernel packet gates remain mandatory. Runtime attachment requires a subsequent lifecycle controller and exact registered flows. Never add addresses from a historical DNS receipt as permanent rules. No hostname, resolver, tenant, port, UID or trust path becomes a product default.
