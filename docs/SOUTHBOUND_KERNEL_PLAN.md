# Scoped southbound kernel policy candidate

This pure compiler complements the existing registry-bound TLS relay and Kubernetes policy contracts for the observed Docker installation. It performs no DNS resolution, socket, file write, subprocess or rule installation. All table/interface/source/destination/transport/endpoint/lease/evidence bindings are explicit. Lab names and addresses in tests are fixtures, not installation defaults.

`tools/materialize_southbound_kernel.py.materialize(config)` returns an uninstalled nftables plan. Config has exactly tableName, guardedInterfaces, existingInterfaces, staticFlows and providerFlows. Selected interfaces must be distinct safe new isolated interface names and exclude observed existing interfaces. The live backend and Gateway-control bridges are not to be guarded by this candidate. A real installer must re-inspect all interfaces, verify dedicated role ownership, install exclusively into an unused private table and read back; this compiler is not that installer and its declaration cannot prove installation facts.

Static flows register exact source/destination IP, protocol, port and purpose (workload-to-Gateway, Gateway-to-adapter, DNS, identity, telemetry); return traffic requires the exact reverse pair/port plus established conntrack state. UDP is limited to the DNS profile. Provider flows include endpointRef, exact governed HTTPS endpoint, source IP, resolved exact IP addresses, bounded leaseSeconds (1..3600), resolutionEvidenceRef and explicit exact private-address exceptions. CGNAT/non-global addresses require exceptions; loopback/link-local/metadata/multicast/unspecified/reserved destinations are always rejected. IPv4/IPv6 are emitted independently; CIDRs and broad Internet allowances are not accepted.

Each provider-address set expires in the kernel. Both outbound and reply packets check membership even for established connections, so an expired lease cannot be bypassed through a previously open socket. No blanket conntrack established/related ACCEPT is generated. The scoped hooks cover host input/output and forwarded packets at priority -150. Their base-chain ACCEPT only leaves unrelated traffic to the existing kernel chains; it does not override a DROP in another base chain. Guarded traffic reaches only the exact permitted flows or a countered DROP. No flush ruleset, alteration of existing Docker chains or shared-host global DROP is emitted.

This is a candidate, not production egress/FQDN acceptance. Fresh resolver evidence, all-answer validation, TTL semantics and fail-closed lease refresh/persistence must be implemented and governed; a declared IP list/evidence reference is not proof of its DNS provenance. Existing relay fixed-host/SNI/hostname checking remains required. Docker embedded DNS may forward through host sockets outside a container's packet path; its configured upstream/service boundary needs explicit readback and scoped policy, not an assumed proof. Direct Semantic/Ingestion bypass, actual bridge forwarding hooks, complete installed IPv4/IPv6 paths, reboot/restart ordering and denied host/direct traffic need their own target-host proofs.

CI runs real nftables in isolated Linux network namespaces with a directly connected veth fixture. Baseline ports 443/8443 both reachable; deny-only plan blocks both; exact timed provider flow permits 443 and denies 8443; lease expiry blocks new connections and a socket opened while the lease was valid. Only local fixture servers are used and namespaces/processes removed; no host/global rules, OUF container, source replay or external provider call. This proves actual kernel input/output rules and expiration semantics in CI. It does not prove Docker bridge hook placement, forwarded packet behavior on the VPS, DNS refresh, workload bypass or release acceptance. Mandatory fixture opt-in: OUF_SOUTHBOUND_KERNEL_TEST=1 as root with ip/nft available. Eight unit cases cover injection/shared-interface exclusion, family/classes/private exceptions, lease/port bounds and exact bidirectional infrastructure flows.
