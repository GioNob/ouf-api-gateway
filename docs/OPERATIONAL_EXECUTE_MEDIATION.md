# Closed operational execute mediation

The profile `ouf.operational-execute.v1` implements the delegated Operational Awareness mediation required by Gateway PET 1.5 and the [platform resilience policy](https://github.com/GioNob/ouf-deploy/blob/main/docs/OUF_RESILIENCE_POLICY.md). It materializes six reviewed READ capabilities into fixed per-capability routes under `/internal/capabilities/v1/execute/`. No arbitrary destination, capability, operation class, workload or egress is accepted.

Global summary/incidents go to the MCP aggregate owner. Four hidden producer capabilities go to their Ingestion or Gateway owners and remain `toolEligible=false`. The materializer compares owner, path, service, workload, coarse scope, actor policy, request/timeout bounds and tool exposure with their governed compiled bindings. Missing, duplicate or changed bindings block generation. Existing public status and Authorization permission mediation can coexist with the new explicit profile.

Each dispatch requires a current OIDC-verified MCP SERVICE bearer plus the existing Gateway-signed HUMAN context, limited to 60 seconds and bound to issuer, audience, workload, tenant, subject, authentication context, original client, scope and role references. The dispatch identity must match that subject/tenant/actor/authentication context and either its original client or the configured MCP workload for a nested aggregate hop. A third service cannot impersonate that delegation. Current owner-local fine Authorization still decides each collection and incident; neither the proof, request hash nor Authorization decision reference is a cached grant.

The Gateway strips bearer, cookies, arbitrary `X-OUF-*` and credential headers, then injects verified identity and roles. Only the two aggregate MCP destinations receive the validated opaque proof and the `mcp-operational-aggregate-v1` marker for further governed owner reads. Producers and public status never receive that proof. Correlation, attempt and idempotency headers must match the closed dispatch envelope. Producer arguments are rebuilt from the validated typed query; cursor-only continuation cannot be combined with replacement filters. Gateway queries cannot acquire Ingestion source scope.

Queries are closed and bounded: UTF-8 JSON up to 64KiB; limit 1–100; timezone-aware `since`; incident lifecycle enum; source filter only for MCP/Ingestion; optional stable snapshot and opaque cursor only for incident producers. Public global cursor schemas remain unchanged pending composition adapter qualification. APISIX upstream retries stay zero: durable finite retry/pause budgets belong to the governed caller, avoiding multiplied retry loops.

Qualification runs actual generated Lua with changed principal, tenant, workload, actor, scope, proof, expiry, correlation and config failures, closed schemas and fixed owner bindings. The required real APISIX/OIDC gate additionally verifies all six destinations and a delegated nested-hop identity, plus unchanged public status and permission boundaries. Numeric OUF bounds are project profiles, not numerical AWS prescriptions. APISIX phase behavior follows its [official serverless documentation](https://apisix.apache.org/docs/apisix/plugins/serverless/).

This is a reviewed materialization profile, not a target deployment or a new authorization grant. The MCP HTTP client and aggregate owner must select these explicit routes and consume the verified context; runtime composition budgets, local Gateway host/SDK, network isolation, target custody, HA and operator delivery checkpoint still need their own evidence. No production keys, email, VPS restart/migration, R9/R10 replay or release acceptance is performed here.


## Global incident cursor opt-in

The global MCP incident dispatch now accepts the same explicit snapshot/continuation modes as incident producers: snapshot=true with bounded filters, or a single lowercase canonical nonzero UUID cursor. Summary remains legacy-only; mixed cursor/filter/snapshot inputs, null/false flags, uppercase/zero UUIDs and unknown fields fail request-validation before owner I/O. No new route, scope, grant or transport retry is introduced. The signed HUMAN delegation and verified marker are retained only to the configured aggregate MCP owner; both producer hops retain their existing hidden exposure and fine authorization.

The matching MCP adapter/manifest is tracked in [MCP PR58](https://github.com/GioNob/ouf-mcp-server/pull/58) and [HTTP contract](https://github.com/GioNob/ouf-mcp-server/blob/main/docs/OPERATIONAL_CURSOR_HTTP.md). Qualification includes JSON Schema positive/negative cases, Lua exact forwarding and real APISIX/OIDC acceptance/rejection. A Gateway schema alone is not evidence of an active target cursor. No page delivery/consultation acknowledgement, checkpoint, actual email, target restart or R9/R10 replay is performed.
