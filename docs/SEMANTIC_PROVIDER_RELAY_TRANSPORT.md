# Semantic provider bounded relay transport

Candidate transport core; no listening socket, installed routes or production admission acceptance.

`tools/semantic_provider_relay.py` wires the existing exact six-query form validator and installed namespace IRI validator to a fixed registered HTTPS provider endpoint. Fetch IRIs become data in a fixed subject-only CONSTRUCT at that endpoint; they never become network destinations. Only outgoing asserted subject triples are returned, with explicit scope metadata. No recursive imports/blank-node closure/inference or complete ontology claim. No LIMIT truncation of fetch: incomplete/oversize bodies fail. Exact candidate RDF inspection and adopted revision pinning remain separate Semantic owner gates.

Installed domains/ports/endpoint/namespace/CIDR/CA bindings are constructor inputs. DNS answers are checked with the existing southbound security policy; all answers must be admissible, and unregistered non-global addresses (including shared address space) are rejected. Connection uses a numeric approved socket address with no second DNS resolution, while TLS SNI and certificate hostname validation use the registered hostname. Provider redirects, response compression, malformed/ambiguous framing, wrong media, oversize and incomplete responses fail closed. Caller bearer/credential headers are not accepted or forwarded. Responses/connections close on every rejection. Search requires bounded JSON result shape/count.

Full elapsed-time bounds cover DNS/TCP/TLS/headers/body via a POSIX main-process deadline. Threaded invocation is rejected; a concurrent adapter must run bounded separate worker processes. This core must not be exposed directly. Trusted Gateway admission/owner bypass protection, API listener, APISIX compiled route policy/identity, network isolation, egress default-deny/FQDN controls, TLS trust/client identities, lifecycle deployment and operational evidence are still required. Application-level pinning is additional control, not OS egress acceptance. No production provider call/deployment performed.

Focused validation: ten existing request grammar tests plus ten new relay tests; TLS fixtures validate actual numeric pin/registered SNI hostname, trusted/untrusted certificate behavior and absence of caller Authorization. Other cases cover six exact forms, fixed CONSTRUCT destination, pre-DNS injection/metadata URI rejection, mixed/forbidden DNS, redirect/media/encoding/size/framing/incomplete body rejection, closure, result bounds, elapsed deadlines and non-main-thread rejection. Fixtures substitute the socket connection to loopback only in test code; production rejects loopback/metadata destinations. CI workflow executes both suites on Python 3.13.


The TLS listener, separate provider-purpose Gateway receipt verifier and additive route materializer are now implemented as candidates; see `SEMANTIC_PROVIDER_ADAPTER.md`. Linux bounded fork workers satisfy the core's main-thread requirement and nested deadlines preserve the full incoming request budget. Production Gateway admission, TLS/runtime compatibility, packaging, kernel isolation/FQDN and release acceptance remain open pending their own evidence.
